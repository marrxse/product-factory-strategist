# Воспроизводимость: даёт ли агент тот же ответ на тот же вход

Задание просит рекомендацию, «которой можно доверять». Доверие требует воспроизводимости: если повторить работу, решение не должно меняться случайно. Мы проверили это двумя способами.

## Что проверяли
1. **Детерминированная часть.** Каждый расчёт из реестра доказательств (`kind=calc`) запускается дважды: вывод должен совпасть, а все числа записи — найтись в выводе (допуск 2% на округление).
2. **Разброс модели в главной точке решения — этапе «Варианты».** Три независимых прогона этапа 4 на рабочей модели агента (Sonnet) с чистым контекстом. На входе только то, что было у агента перед этим этапом: бриф, исследование и реестр (`input/`). Готовых вариантов, стратегий и документов после выбора прогоны не видели. Каждый прогон шёл по тому же навыку `skills/options/SKILL.md`; критик в прогонах не участвовал, возражения формулировал сам прогон.

Сравниваем с исходным результатом демо: рекомендацию, набор типов вариантов, обязательные «оставить» и «закрыть», ошибки формы (`sf.py validate`) и опору на реестр (ссылки `[E…]` и их пересечение с исходным).

## Как повторить
```bash
python3 eval/repro.py
```
Скрипт пересчитывает раздел «Результаты» ниже. Новые прогоны вариантов добавляются папкой `run-N/options.md` (промпт прогона — в `PROMPT.md`).

## Выводы (2026-11-06)
- **Решение воспроизводится.** Все три независимых прогона рекомендовали тот же вариант, что и исходная работа: B — защиту близких. Набор вариантов почти тот же: «оставить», «закрыть», «бесплатно в тарифе», «компенсация потерь», «защита близких» есть во всех четырёх результатах. Отличается пятый-шестой вариант: в исходной работе — B2B (добавлен после сравнения с обычным чатом), в прогонах — «платит партнёр» и формулировка «переупаковать».
- **Расчёты воспроизводятся полностью:** оба скрипта дают одинаковый вывод при повторном запуске, все числа записей реестра находятся в выводе. Проверка нашла и закрыла один пробел: предельная стоимость привлечения в записи E49 раньше выводилась из формулы вручную, теперь её печатает скрипт.
- **Без проверки формы модель ошибается одинаково.** Прогоны шли без хука и без `validate`, и в каждом из трёх нашлась синтетика, поданная как довод спроса, и числа без источника — ровно то, что агент запрещает правилами. В обычной работе хук после каждой записи ловит это до закрытия этапа. Это прямое подтверждение, что проверка кодом нужна, а не просьба к модели.
- **Опора на реестр разная по объёму, но не по сути:** прогоны ссылаются на 26–34 записи против 12 у исходной работы (у прогонов был реестр с записями, добавленными уже после этапа 4: конкуренты, интерфейс, поведение), общая доля ссылок — 23–27%.
- **Чего эта проверка не доказывает:** три прогона — малая выборка; прогоны шли без критика; все на одной модели. Проверка на другой модели и на другом брифе — следующий шаг.
- **Стоимость:** три прогона на Sonnet — около 1,2 $ по журналу затрат (часть записей может дописаться позже) и около полутора минут каждый.
