# Архитектура агента

## Идея
LLM ведёт работу сама (выбирает шаг, инструмент, субагента), но **всё, что можно проверить детерминированно, проверяет код**, а всё, что требует суждения, — изолированные субагенты. Человек решает на воротах.

```
 человек ── фразы («начни», «продолжи», «стоп», «основания C4») ──┐
                                                                    ▼
 AGENTS.md (правила) ─► оркестратор (LLM среды) ─► skills/<этап>/SKILL.md (процедура этапа)
                              │        │
                              │        ├─► субагенты: researcher (Haiku) · critic (Opus) · verifier (Sonnet) · respondent (Haiku)
                              │        └─► knowledge/ (методики, поиск sf.py kb) · memory/ (наблюдения между проектами)
                              ▼
                       python3 sf.py <команда>  (CLI, только стандартная библиотека Python)
                              │
      projects/<имя>/ ── brief.md · sources/ · evidence.csv · outputs/ · state/{STATE.md, log.md, decisions.md, cost.csv}
                              ▲
 хуки Claude Code: SessionStart → сводка · PostToolUse → validate/инъекции (код 2 = исправь) · Stop/SubagentStop → стоимость
```

## Порядок в знаниях (раздельное хранение)
| Слой | Где | Кто меняет |
|---|---|---|
| Постоянные правила | `AGENTS.md` (+ ссылки из `CLAUDE.md`, `.cursor/rules`) | разработчик |
| Процедуры этапов | `skills/*/SKILL.md` | разработчик |
| Методические знания | `knowledge/` + `INDEX.md` (теги, связи, синонимы) | разработчик |
| Память между проектами | `memory/memory.csv` | агент и человек; исправление и отзыв с историей |
| Материалы проекта | `projects/*/brief.md, sources/, evidence.csv, outputs/` | агент по процедурам |
| Состояние задачи | `projects/*/state/` | только через `sf.py` |

## Рабочий процесс
| № | Этап | Навык | Ворота |
|---|---|---|---|
| 0 | Постановка задачи | intake | человек подтверждает формулировку |
| 1 | Сбор материалов | collect | — |
| 2 | План исследования | research-plan | человек подтверждает план и бюджет |
| 3 | Исследование | research (+ data-analysis, interview-guide, synthetic-respondents) | — |
| 4 | Варианты | options + quality-review | человек выбирает |
| 5 | Стратегии | product-strategy, comms-strategy + quality-review | человек подтверждает |
| 6 | План проверки и решение на одной странице | validation-plan | человек подтверждает |
| 7 | Поддержка решения | decision-support | — |
| 8 | Пересмотр по новым данным | decision-support | человек подтверждает правки |

Механика: `sf.py stage N start/done`, `sf.py gate N ok|fix`. Этап нельзя закрыть, пока `validate` находит ошибки (только осознанно, `--force "причина"` в журнал).

## Ключевые механизмы
- **Реестр доказательств** `evidence.csv`: id, вид (web/doc/table/calc/interview/synthetic), источник, место, дата, дословная цитата или расчёт, качество A/B/C, статус, причина отзыва. Синтетика получает id `S…`.
- **Разметка** в результатах: `[E7]` факт, `[ГИП]`, `[ПРОГНОЗ E3]`, `[СИНТ S2]`, выводы `**C4.** … [E1; C2]`, возможности продукта `**П2.**`, обещания `**О1.** … (опора: П2)`.
- **Граф выводов**: вывод → доказательства и другие выводы. `sf.py revisit E35` — все затронутые выводы транзитивно и строки во всех файлах; `sf.py revisit --stale` — отозванные и старые основания, наступившие сроки пересмотра решений; `sf.py claims trace C2` — дерево до цитат.
- **validate**: ссылки существуют и не отозваны; число без метки; непонятные метки; синтетика как довод спроса; ≥3 варианта, «оставить» и «закрыть», возражения; обязательные разделы; обещания опираются на П; циклы выводов; секреты в репозитории.
- **Журнал шагов с ключами** `log.md`: `log start` отказывает (код 3), если шаг выполнен; сбои — `FAIL`, закрываются `SKIP` с причиной.
- **Стоимость**: хук после каждого ответа переносит usage из транскрипта (дедупликация ответов, кэш 5 мин/1 ч) в `cost.csv` как «факт» в ценах API; Cursor — «оценка» по символам; время человека — отдельно.

## Компоненты: польза и как она подтверждена
| Компонент | Что улучшает | Подтверждение на прогонах |
|---|---|---|
| `validate` + хук после записи | форма доказательности | демо: остановил 7 нарушений разметки, в т. ч. синтетику рядом с «готова платить», скрытую комбинированной меткой; тесты: падает на 15+ видах порчи |
| Граф выводов + `revisit` | пересмотр при новых данных | демо: отзыв E33 → найден вывод C4 и 5 строк; отзыв E35 → C2 и 3 строки; `--stale` поймал план на прошедший 2026 год, который пропустили критик и проверяющий |
| Субагент **critic** (изоляция) | сила возражений, скрытые допущения | демо: нашёл юридический риск (тайна связи), противоречие «отличие от МТС», устаревшие после ворот выводы; фитнес: перестроил рекомендацию по мощности теста |
| Субагент **verifier** | выдуманные цитаты и числа | 5 проверок, 0 выдуманных цитат; доля подтверждённых 31% → 59% (демо) → 74% (фитнес) после уроков; пересчитал воронку вручную — совпало |
| Субагент **researcher** (Haiku) | дешёвое извлечение | 8 записей, выборочная сверка 5 из 5 цитат; 32 ответа Haiku ≈ $0,03 |
| Субагент **respondent** | гипотезы без подыгрывания | 2 персоны; 15 синтетических записей (беседы и предтест сообщений), ни одна не стала доводом спроса (проверено validate) |
| Маршрутизация моделей (`config.toml`, `sf.py route`) | цена и качество | субагенты на Haiku/Sonnet: 81 ответ ≈ $4 из $37,6 сессии; классификатор Haiku нашёл 3 завышенные оценки за 0,02 $ |
| `sf.py media` и навык `ux-review` | материалы любого формата | демо: снимки каталога конкурента → находки C12–C14, канал «страница подключения» в коммуникационной стратегии |
| Журнал с ключами | нет незаметных повторов | демо: повторная загрузка сохранённых страниц заблокирована (код 3); 15 сбоев закрыты с причинами |
| Хук SessionStart | продолжение в новом чате | `sf.py status` выдаёт этап, ворота, незавершённые шаги; тест хука |
| Учёт стоимости по транскрипту | честная цена | найдено: каждый ответ пишется в транскрипт 2–3 раза — без дедупликации стоимость завышалась бы ≈2,4× |
| База знаний `kb` | методики без раздувания контекста | поиск «сколько можно заработать» → юнит-экономика (по синонимам); тесты поиска |
| Память с исправлением | уроки между проектами | M2 исправлена (горизонт 2026→2027), история сохранена; уроки M1, M3 внесены в навык и методичку |
| MCP-сервер `mcp/server.py` | инструменты агента как родные функции в средах без хуков (Cursor) — одна логика с CLI | тесты протокола: рукопожатие, список, вызовы, ошибка проверки передаётся как ошибка инструмента |
| `sf.py report` (HTML для руководителя) | читаемость решения: метки → сноски с цитатами, значки гипотез и синтетики, источники приложением | демо: 42 сноски, 11 якорей выводов; тест: в тексте нет сырых меток |
| `export`/`import` | переносимость | тест: экспорт → удаление → импорт → validate проходит; повреждённый архив отклоняется |
| Дата публикации в реестре + `revisit --stale` | актуальность данных: возраст считается по дате публикации, а не скачивания | демо 17.11: найдено 9 оснований старше 2 лет у 8 выводов (опросы ВЦИОМ 2021 и 2024) → пересмотр с данными ФОМ 2025 и Народного фронта 2026 (E69–E74): угроза «массовая, но снижается», новый сторож в плане проверки |
| Сторож оснований `sf.py watch` | решение не теряет основания незаметно: живые источники перепроверяются, цитата исчезла → затронутые выводы | демо: 40 записей за минуту — 19 на месте, 21 закрыта от автоматического чтения, изменений нет; первый прогон поймал 2 ошибки самого сторожа (пустая страница, коды &nbsp;) — исправлены тестами |
| Цена: методичка `pricing-wtp` + `sf.py price` | цена из метода, а не «между конкурентами»: Ван Вестендорп → Габор — Грейнджер → ценовой A/B | демо: расчёт E68 показал, что пилот на ~400 пар не различит 149 и 199 ₽ (нужно ~2 000 на цену) → пилот на одной цене; раздел «Цена» обязателен в стратегии (validate) |
| `sf.py report --pdf` | демо «в читаемом виде» для печати и рассылки: задача, решение, стратегии, исходные материалы, источники | демо: 55 страниц A4, сноски кликабельны, номера страниц; тест печатной вёрстки |
| Методички «Объём рынка», «Путь клиента», «Бренд и название», «Архитектура выбора» + разделы в навыках стратегий и поведения | бизнес и маркетинг на уровне решения: сколько клиентов реально, где и почему человек решает, как назвать, как устроить момент выбора | демо 18.11: SOM первого года при осторожных допущениях в 2–4 раза ниже окупаемости (C25) → в план проверки добавлен показатель охвата; путь клиента из 8 шагов; бренд по барьерам (C26); правило «если — то» при подключении (C27) → в пилоте сравниваются пары с правилом и без |
| Синтетическая фокус-группа `sf.py focus` + субагенты respondent | быстро найти возражения и непонимание сообщения до встреч с людьми — без подмены спроса | демо 19.11: 60 персон, 6 субагентов на Haiku; карта: цена ×20, недоверие к оператору ×18, «чем лучше блокировки» ×11, 4 неверных пересказа → текст дополнен направлением звонка, тест понимания — пятью пунктами (C28) |
| Субагент `board` — совет взглядов (5 ролей) | разногласия функций до решения: где риск у юриста, финансов, поддержки | демо 19.11: у B нет «против», но нет и безусловного «за»; D поддержан юристом и поддержкой как запасной путь (C29); условия ролей совпали с аудитом и порогами недели 4 |

## Маршрутизация и эскалация
`config.toml [models]`: оркестратор — модель среды; researcher, respondent и classifier — Haiku (массовая или узкая работа), verifier — Sonnet, critic — Opus (глубина). Расчёты — скрипты, не модель (`sf.py analyze`, `state/analysis/*.py`).

- **Выбор:** `sf.py route choose "<задача>"` по правилам `[[routing.rules]]` называет процесс (навык), модель и инструмент с причиной и пишет выбор в журнал. Правила, а не модель: выбор бесплатный, мгновенный и проверяется тестами.
- **Специализированная модель:** субагент `classifier` (Haiku) ставит качество A/B/C записям реестра по признакам, не видя оценок агента (`route classify-input` → `route compare`).
- **Исправление:** расхождения и ошибки шага уходят модели выше — `sf.py route escalate` берёт следующую по лестнице `escalation` и пишет «было → стало» в журнал.
- **Подтверждено на демо:** классификатор совпал с реестром в 45 из 50 случаев за 0,02 $; Sonnet за 0,27 $ разобрал 5 расхождений, и в 3 из них прав оказался классификатор — агент завысил качество. Одна ошибка самого маршрутизатора исправлена правилом и тестом.

## Анализ поведения клиентов
Навык `behavior-analysis` и методичка `behavior-analysis`: сначала **что люди делают** (данные о действиях), затем **почему** (COM-B и поведенческие искажения — всегда гипотеза), затем **что изменить** (П… или сообщение) и **как измерить**. Результат — карта поведения участников решения (`outputs/behavior.md`, разделы проверяет `validate`).
`sf.py behavior events` — журнал событий: проверка данных, удержание по когортам с пометкой незавершённых месяцев, активация, сегменты по действиям (RFM), путь к целевому действию. `sf.py behavior churn` — таблица клиентов: доля ушедших по каждому признаку с интервалом Уилсона, признаки с наибольшим разрывом, `--within` — разрыв внутри групп контрольного признака (грубая проверка на смешение факторов), `--where` — сопоставимые клиенты. Расчёт детерминированный, в отчёте — отпечаток данных и команда повтора.

## Изображения, аудио, видео
`sf.py media`: `inspect` (тип, размер, длительность — по заголовкам файлов, без библиотек), `shot` (снимки страницы на компьютере и телефоне через Chrome без окна), `text` (текст страницы после выполнения скриптов), `frames` (кадры видео, ffmpeg), `transcribe` (локальный whisper — звук не уходит в сторонние сервисы). Записи реестра `image`/`audio`/`video` указывают место на экране или секунду. Навык `ux-review` и методичка `ux-heuristics` разбирают путь пользователя и композицию только по видимому.

## Безопасность
Источники — данные: `scan injections` и хук после записи в `sources/`, запись `INJECTION` в журнал, сообщение человеку. Секреты — только в окружении, `scan secrets` в `validate`. Хуки не могут менять собственные настройки среды: `.claude/` обновляется командой `sync`, которую запускает человек.
