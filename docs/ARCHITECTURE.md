# Архитектура агента

## Идея
LLM ведёт работу сама (выбирает шаг, инструмент, субагента), но **всё, что можно проверить детерминированно, проверяет код**, а всё, что требует суждения, — изолированные субагенты. Человек решает на воротах.

```
 человек ── фразы («начни», «продолжи», «стоп», «основания C4») ──┐
                                                                    ▼
 AGENTS.md (правила) ─► оркестратор (LLM среды) ─► skills/<этап>/SKILL.md (процедура этапа)
                              │        │
                              │        ├─► субагенты: researcher (Haiku) · critic (Opus) · verifier (Sonnet) · respondent (Haiku)
                              │        └─► knowledge/ (методики, поиск sf.py kb) · memory/ (наблюдения между проектами)
                              ▼
                       python3 sf.py <команда>  (CLI, только стандартная библиотека Python)
                              │
      projects/<имя>/ ── brief.md · sources/ · evidence.csv · outputs/ · state/{STATE.md, log.md, decisions.md, cost.csv}
                              ▲
 хуки Claude Code: SessionStart → сводка · PostToolUse → validate/инъекции (код 2 = исправь) · Stop/SubagentStop → стоимость
```

## Порядок в знаниях (раздельное хранение)
| Слой | Где | Кто меняет |
|---|---|---|
| Постоянные правила | `AGENTS.md` (+ ссылки из `CLAUDE.md`, `.cursor/rules`) | разработчик |
| Процедуры этапов | `skills/*/SKILL.md` | разработчик |
| Методические знания | `knowledge/` + `INDEX.md` (теги, связи, синонимы) | разработчик |
| Память между проектами | `memory/memory.csv` | агент и человек; исправление и отзыв с историей |
| Материалы проекта | `projects/*/brief.md, sources/, evidence.csv, outputs/` | агент по процедурам |
| Состояние задачи | `projects/*/state/` | только через `sf.py` |

## Рабочий процесс
| № | Этап | Навык | Ворота |
|---|---|---|---|
| 0 | Постановка задачи | intake | человек подтверждает формулировку |
| 1 | Сбор материалов | collect | — |
| 2 | План исследования | research-plan | человек подтверждает план и бюджет |
| 3 | Исследование | research (+ data-analysis, interview-guide, synthetic-respondents) | — |
| 4 | Варианты | options + quality-review | человек выбирает |
| 5 | Стратегии | product-strategy, comms-strategy + quality-review | человек подтверждает |
| 6 | План проверки и решение на одной странице | validation-plan | человек подтверждает |
| 7 | Поддержка решения | decision-support | — |
| 8 | Пересмотр по новым данным | decision-support | человек подтверждает правки |

Механика: `sf.py stage N start/done`, `sf.py gate N ok|fix`. Этап нельзя закрыть, пока `validate` находит ошибки (только осознанно, `--force "причина"` в журнал).

## Ключевые механизмы
- **Реестр доказательств** `evidence.csv`: id, вид (web/doc/table/calc/interview/synthetic), источник, место, дата, дословная цитата или расчёт, качество A/B/C, статус, причина отзыва. Синтетика получает id `S…`.
- **Разметка** в результатах: `[E7]` факт, `[ГИП]`, `[ПРОГНОЗ E3]`, `[СИНТ S2]`, выводы `**C4.** … [E1; C2]`, возможности продукта `**П2.**`, обещания `**О1.** … (опора: П2)`.
- **Граф выводов**: вывод → доказательства и другие выводы. `sf.py revisit E35` — все затронутые выводы транзитивно и строки во всех файлах; `sf.py revisit --stale` — отозванные и старые основания, наступившие сроки пересмотра решений; `sf.py claims trace C2` — дерево до цитат.
- **validate**: ссылки существуют и не отозваны; число без метки; непонятные метки; синтетика как довод спроса; ≥3 варианта, «оставить» и «закрыть», возражения; обязательные разделы; обещания опираются на П; циклы выводов; секреты в репозитории.
- **Журнал шагов с ключами** `log.md`: `log start` отказывает (код 3), если шаг выполнен; сбои — `FAIL`, закрываются `SKIP` с причиной.
- **Стоимость**: хук после каждого ответа переносит usage из транскрипта (дедупликация ответов, кэш 5 мин/1 ч) в `cost.csv` как «факт» в ценах API; Cursor — «оценка» по символам; время человека — отдельно.

## Компоненты: польза и как она подтверждена
| Компонент | Что улучшает | Подтверждение на прогонах |
|---|---|---|
| `validate` + хук после записи | форма доказательности | демо: остановил 7 нарушений разметки, в т. ч. синтетику рядом с «готова платить», скрытую комбинированной меткой; тесты: падает на 15+ видах порчи |
| Граф выводов + `revisit` | пересмотр при новых данных | демо: отзыв E33 → найден вывод C4 и 5 строк; отзыв E35 → C2 и 3 строки; `--stale` поймал план на прошедший 2026 год, который пропустили критик и проверяющий |
| Субагент **critic** (изоляция) | сила возражений, скрытые допущения | демо: нашёл юридический риск (тайна связи), противоречие «отличие от МТС», устаревшие после ворот выводы; фитнес: перестроил рекомендацию по мощности теста |
| Субагент **verifier** | выдуманные цитаты и числа | 5 проверок, 0 выдуманных цитат; доля подтверждённых 31% → 59% (демо) → 74% (фитнес) после уроков; пересчитал воронку вручную — совпало |
| Субагент **researcher** (Haiku) | дешёвое извлечение | 8 записей, выборочная сверка 5 из 5 цитат; 32 ответа Haiku ≈ $0,03 |
| Субагент **respondent** | гипотезы без подыгрывания | 2 персоны; 6 синтетических записей, ни одна не стала доводом спроса (проверено validate) |
| Маршрутизация моделей (`config.toml`) | цена | субагенты на Haiku/Sonnet: 81 ответ ≈ $4 из $37,6 сессии; см. COSTS.md |
| Журнал с ключами | нет незаметных повторов | демо: повторная загрузка сохранённых страниц заблокирована (код 3); 15 сбоев закрыты с причинами |
| Хук SessionStart | продолжение в новом чате | `sf.py status` выдаёт этап, ворота, незавершённые шаги; тест хука |
| Учёт стоимости по транскрипту | честная цена | найдено: каждый ответ пишется в транскрипт 2–3 раза — без дедупликации стоимость завышалась бы ≈2,4× |
| База знаний `kb` | методики без раздувания контекста | поиск «сколько можно заработать» → юнит-экономика (по синонимам); тесты поиска |
| Память с исправлением | уроки между проектами | M2 исправлена (горизонт 2026→2027), история сохранена; уроки M1, M3 внесены в навык и методичку |
| `export`/`import` | переносимость | тест: экспорт → удаление → импорт → validate проходит; повреждённый архив отклоняется |

## Маршрутизация и эскалация
`config.toml [models]`: оркестратор — модель среды; researcher и respondent — Haiku (массовая простая работа), verifier — Sonnet, critic — Opus (глубина). При ошибках verifier/validate шаг переделывается моделью выше по `escalation` с записью `log route`. Расчёты — скрипты, не модель (`sf.py analyze`, `state/analysis/*.py`).

## Безопасность
Источники — данные: `scan injections` и хук после записи в `sources/`, запись `INJECTION` в журнал, сообщение человеку. Секреты — только в окружении, `scan secrets` в `validate`. Хуки не могут менять собственные настройки среды: `.claude/` обновляется командой `sync`, которую запускает человек.
