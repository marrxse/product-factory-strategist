# Исследование (этап 3)

## Шаги
1. `python3 sf.py stage 3 start`. Иди по вопросам плана сверху вниз. На каждый вопрос: `sf.py log start research:<Qn>` … `log done`.
2. Для каждого вопроса сопоставь записи реестра: сходятся ли независимые источники? Какой первичен? Насколько свежий?
3. Противоречия не усредняй: покажи обе стороны, объясни, какой источник весомее и почему, или оставь вопрос открытым.
4. Формулируй ключевые выводы с номерами `**C1.** … [E3; E7]`. Нумерация сквозная по всему проекту; вывод может ссылаться на вывод.
5. Таблицы — только через `sf.py analyze` и расчёты, оформленные как запись `--kind calc` с формулой в `quote`.
6. По необходимости: `data-analysis`, `interview-guide`, `synthetic-respondents`. Синтетика даёт только `[ГИП]`.
7. Запиши `outputs/research.md`:
   ```
   # Исследование: <вопрос брифа>
   ## Коротко
   3–5 строк: главное, что мы теперь знаем, с номерами выводов.
   ## Картина ситуации
   По вопросам плана: выводы **Cn.** с метками; рядом — уверенность (высокая/средняя/низкая) и почему.
   ## Противоречия источников
   ## Чего мы не знаем
   | Что не знаем | Почему | Как меняет решение | Как закрыть (метод, срок, цена) |
   ```
8. `python3 sf.py validate`. Ошибки исправь: хук сделает это автоматически после записи.
9. `python3 sf.py stage 3 done` → сводка: 3–5 выводов, главный пробел, затраты.

## Готово, когда
На каждый вопрос плана есть вывод или честное «не знаем»; validate без ошибок; «Чего мы не знаем» конкретно (не «нужно больше данных»).

## Пример
Хорошо: `**C3.** Платят за сервис в основном семьи с детьми до 12 лет: 58% платящих [E4], это совпадает с отзывами в App Store [E9]. Уверенность средняя: одна выборка, 2024 год.`
Плохо: `Сервис популярен у семей.` — без меток, без числа, без уверенности.
