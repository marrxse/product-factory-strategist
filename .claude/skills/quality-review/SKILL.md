# Контроль смыслового качества

`validate` проверяет форму. Этот навык проверяет, можно ли выводам доверять.

## Шаги
1. `python3 sf.py validate` — сначала форма, ошибок быть не должно.
2. `python3 sf.py sample` → `state/verify-sample.md`: все числа ключевых файлов + 10 случайных утверждений (seed из config.toml, выборка воспроизводима).
3. Субагент `verifier` проверяет выборку по источникам и возвращает вердикты: да / частично / нет. Доля подтверждённых = да ÷ всего; «частично» — не подтверждено.
4. Субагент `critic` (не видел процесса) оценивает результаты по `knowledge/quality-rubric.md`: 7 критериев × 0–2.
5. Тесты (делает критик, сверяешь ты):
   - **Что бы нас переубедило:** для рекомендации — факты, при которых выбрали бы другой вариант.
   - **Различие вариантов:** по каждой паре — разница ставки (кому / что / зачем).
   - **Согласованность (этап 5):** таблица «обещание О → возможность П → вывод C → доказательство E».
6. Пороги из `config.toml [quality]`: рубрика ≥ `rubric_min`, подтверждено ≥ `verified_share_min`. Не прошли — исправь найденное и повтори. Не больше `max_rework_cycles` циклов, затем покажи отчёт человеку как есть, без маскировки.
7. Запиши `outputs/quality-report.md`:
   ```
   # Отчёт о качестве (этап N, цикл K)
   ## Итог
   Рубрика X/14 (порог …), подтверждено Y из Z (…%), вердикт: прошло / не прошло.
   ## Проверка утверждений
   | № | Где | Вердикт | Пояснение |
   ## Рубрика
   | Критерий | Балл | Почему |
   ## Что бы нас переубедило
   ## Различие вариантов
   ## Согласованность обещаний (этап 5)
   ## Что исправлено после проверки
   ## 5 вопросов ревьюера
   ```

## Чего не делать
- Не оценивай собственную работу сам вместо critic и verifier: смысл навыка — независимый взгляд.
- Не округляй долю подтверждённых в свою пользу и не удаляй неудобные строки из выборки.
