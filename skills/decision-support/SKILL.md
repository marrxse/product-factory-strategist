# Поддержка решения и пересмотр (этапы 7–8)

## Запись решения (этап 7) — `state/decisions.md`
```
## Р1. <что решили> (принято ГГГГ-ММ-ДД, кем)
- Основания: C2, C5 (ключевые доказательства: E3, E7)
- Ответственный: <роль, без персональных данных>
- Показатель и цель: <метрика> <диапазон> [ПРОГНОЗ C…]
- Пересмотреть до: ГГГГ-ММ-ДД
- Условия досрочного пересмотра: если <факт> — например, отзыв E3, падение метрики-сторожа
- Обязательства: [ ] <что сделать> — <роль> — до ГГГГ-ММ-ДД
- Статус: действует | пересмотрено (дата, см. Р…) | отменено (причина)
```
Решения не удаляются: отменённое остаётся с причиной. Запиши итог в память: `sf.py memory add` (слой памяти), как наблюдение агента.

## «Что решать сейчас» и «что устарело»
1. `python3 sf.py revisit --stale`: отозванные основания; данные, опубликованные больше двух лет назад (по полю `published`); источники, которые давно не сверяли; записи без даты публикации; наступившие сроки пересмотра.
2. `python3 sf.py watch` — сторож оснований: заново открывает веб-источники и проверяет, на месте ли цитаты. «ИЗМЕНИЛОСЬ» — повод для этапа 8; «недоступен» — проверь позже, это не изменение; «не сравнить» — цитата была выдержкой, а не дословной строкой.
3. Просроченные обязательства (`[ ]` с прошедшей датой).
4. Покажи человеку списком: что решить сейчас, вариант по умолчанию, чем грозит откладывание.

## Пересмотр при новых данных (этап 8)
Повод — новые сведения от человека, «ИЗМЕНИЛОСЬ» у сторожа или старые данные в `revisit --stale`.
1. `sf.py stage 8 start`. Новое сведение → `sf.py evidence add` (новая запись), устаревшее → `sf.py evidence revoke E… --reason "…"`.
2. `python3 sf.py revisit E…` — список затронутых выводов (транзитивно) и строк во всех файлах.
3. Для каждого затронутого вывода:
   | Вывод | Было | Стало | Что меняется в решении |
   Если вывод держится на других основаниях — он остаётся, отметь это.
4. Проверь условия пересмотра решений в `decisions.md`.
5. `sf.py stage 8 done` → покажи таблицу «было → стало», спроси подтверждение. После «ок» внеси правки в outputs/, запиши `sf.py log correction …`, обнови decisions.md (новое решение со ссылкой на старое).

## Чего не делать
- Не переписывай выводы молча: каждое изменение — через «было → стало» и подтверждение.
- Не удаляй отозванные записи из реестра: история оснований — часть прозрачности.
