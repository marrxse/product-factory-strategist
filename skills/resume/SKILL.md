# Продолжение после перерыва

## Когда применять
«Продолжи», новая сессия, возврат после «стоп» или сбоя.

## Шаги
1. `python3 sf.py status`. Нет активного проекта → `python3 sf.py list` и спроси, какой открыть (по умолчанию — единственный или последний).
2. Прочитай `state/STATE.md` проекта целиком и последние 20 строк `state/log.md`.
3. Разбери «Незавершённые шаги» из вывода `status`:
   - `START` без `DONE`: проверь, есть ли результат шага (файл, запись в `evidence.csv`). Есть → `sf.py log done <ключ> "подтверждено при возобновлении"`. Нет → выполни шаг заново как обычно (ключ тот же).
   - `FAIL`: прочитай причину; если она устранима — повтори, иначе пометь пробел и `sf.py log skip <ключ> "причина"`.
4. Если этап в статусе «ждёт решения» — не продолжай работу, а снова покажи человеку результат этапа и вопрос ворот.
5. Покажи человеку сводку в формате:
   ```
   Этап N — <название> · где остановились: … · сделано: … · дальше: … · нужно от вас: …
   ```
6. Продолжай с раздела «Дальше» STATE.md.

## Готово, когда
Человек видит, где мы остановились, ни один выполненный шаг не повторён молча, работа идёт со следующего шага.

## Чего не делать
- Не перечитывай все источники и не пересоздавай `outputs/` «на всякий случай».
- Не полагайся на память прошлого чата: истина — только файлы `state/`.

## Пример
Хорошо: «Этап 3 — Исследование · остановились: разобрано 4 из 6 источников (последний шаг collect:fetch:rbc.ru завершён) · дальше: сопоставить источники по вопросу Q2 · от вас ничего не нужно».
Плохо: «Давайте начнём с уточнения задачи» — при подтверждённом брифе.
