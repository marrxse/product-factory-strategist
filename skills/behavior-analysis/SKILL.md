# Анализ поведения клиентов

Методика — `python3 sf.py kb поведение` → `knowledge/behavior-analysis.md`. Правило: **поведение важнее слов**. Сначала действия (данные), затем механизм (гипотеза с названием), затем вмешательство и способ его измерить.

## 1. Что делают — данные о действиях
| Что есть | Команда | Что получишь |
|---|---|---|
| Журнал событий (`user_id, date, event[, value]`) | `python3 sf.py behavior events sources/<файл>.csv --activation <событие> --target <событие>` | проверка данных, удержание по когортам, активация, поведенческие сегменты (RFM), путь к целевому действию |
| Таблица клиентов с признаком ухода | `python3 sf.py behavior churn sources/<файл>.csv --target <колонка> --positive <значение>` | доля ушедших по каждому признаку с 95% интервалом, признаки с наибольшим разрывом |
| Агрегированные когорты | `python3 sf.py analyze` + скрипт в `state/analysis/` | как в навыке `data-analysis` |
| Только опросы и отзывы | частоты «N из M», различие между тем, что говорят, и тем, что делают | помечай: заявленное, а не наблюдаемое |
Отчёт команды ложится в `state/analysis/`. Числа из него — в реестр как `calc` со ссылкой на отчёт:
`python3 sf.py evidence add --kind calc --source state/analysis/<файл>-behavior.md --locator "<раздел>" --quote "<число и база>" --quality A` (качество A, только если данные первичные; учебные и чужие выборки — C).

## 2. Почему — механизм
Для каждого участника решения (кто пользуется, кто платит, кто влияет) пройди COM-B: способность, возможность, мотивация. Назови искажение из таблицы методички, если оно объясняет разрыв между нуждой и действием. Механизм — всегда `[ГИП: <искажение>]`, пока его не подтвердил эксперимент или наблюдаемое поведение.
Различай: **заявленное** (опрос: «считаю маловероятным») и **наблюдаемое** (журнал: «не включил функцию»). Синтетика `[СИНТ S…]` — только как источник гипотез о механизме.

## 3. Что изменить
Для каждого барьера — одно вмешательство: в продукт (П…), если провал в способности или возможности; в сообщение (О…), если в мотивации. У каждого — способ измерить: какой показатель, с чем сравниваем, какой порог. Тёмные паттерны запрещены (методичка, раздел «Этика»).

## 4. Результат — `outputs/behavior.md`
Разделы проверяет `validate`.

### Участники и целевые действия
Кто что должен сделать, чтобы решение сработало: пользователь, плательщик, влияющий.

### Что люди делают
Наблюдаемое и заявленное поведение с источниками [E…]; отдельно — где данных о действиях нет.

### Карта поведения
Таблица: участник · триггер · целевое действие · что мешает (COM-B, искажение) · что поможет (П… / сообщение) · как измерим. Ключевые выводы — `**C….**`.

### Следствия для решения
Что меняется в вариантах, продуктовой стратегии, коммуникации и плане проверки — со ссылками на выводы.

### Чего мы не знаем о поведении
Какие действия не наблюдали, почему, как закрыть: журнал событий, когорты, эксперимент, интервью о последнем случае.

## Чего не делать
- Строить сегменты по возрасту и полу вместо действий.
- Выдавать корреляцию из таблицы оттока за причину.
- Называть механизм фактом без эксперимента.
- Использовать закрытые данные о клиентах компании: только открытые данные и материалы пользователя без персональных данных.
