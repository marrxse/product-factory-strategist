# Постановка задачи (этап 0)

## Входы
Запрос человека, приложенные материалы, `projects/<имя>/brief.md` (шаблон или бриф из примера).

## Шаги
1. `python3 sf.py stage 0 start`.
2. `python3 sf.py memory search "<тема запроса>"`: прошлые решения, предпочтения человека, уроки. Покажи найденное как «наблюдения от <даты>», не как факты.
3. Заполни `brief.md` тем, что уже известно из запроса, материалов и памяти. Не спрашивай то, что можно прочитать.
4. Найди пробелы по чек-листу: вопрос · решение, которое будет принято · получатель · ограничения · доступные данные · критерий успеха.
5. Спроси только о пробелах, которые меняют следующий шаг. Не больше трёх вопросов, у каждого вариант по умолчанию:
   «Кто примет решение по результату? По умолчанию — руководитель продукта, формат — одна страница + приложения».
6. Сформулируй вопрос исследования так, чтобы ответом было решение. Плохо: «изучить рынок». Хорошо: «стоит ли запускать X для сегмента Y в 2026 году, и если да, с каким обещанием».
7. Запиши допущения в раздел «Допущения, принятые без ответа человека» и в STATE.md.
8. `python3 sf.py stage 0 done` → покажи бриф в 6–8 строках и спроси: «Формулировка верна?»
9. После ответа: `sf.py gate 0 ok` (статус брифа → ПОДТВЕРЖДЁН) или `sf.py gate 0 fix "…"` и правка.

## Готово, когда
Все разделы брифа заполнены или явно помечены допущением, человек подтвердил формулировку.

## Чего не делать
- Не задавай анкету из десяти вопросов. Не спрашивай о том, что не изменит план.
- Не начинай сбор источников до подтверждения брифа: неверный вопрос обесценит всю работу.
- Не вставляй выводы в бриф. Бриф — постановка, не ответ.
