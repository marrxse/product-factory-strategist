# Ценностное предложение

Связь: работа пользователя → боль/выгода → свойство продукта, которое её закрывает → доказательство.

## Шаблон
Для <сегмент с работой>, которые <ситуация/боль>, <продукт> — это <категория>, который <главная польза>. В отличие от <текущего способа>, мы <отличие, которое можно проверить>.

## Проверка, что предложение настоящее
1. Польза названа в единицах пользователя (время, деньги, риск, усилие), а не в функциях.
2. Отличие проверяемо: его можно показать за минуту или подтвердить фактом.
3. Свойство продукта, обеспечивающее пользу, существует (П… в продуктовой стратегии) или запланировано со сроком.
4. Есть сегмент, для которого альтернатива хуже, — назван и оценён.

Хорошо: «Отчёт о расходах семьи за 2 минуты вместо часа в таблице: категории расставляются автоматически по выпискам банков».
Плохо: «Удобный инновационный сервис для всей семьи».

## Связь с деньгами
Польза → какое поведение она меняет (чаще пользуются, дольше остаются, платят) → какая метрика → какой доход. Без этой цепочки ценностное предложение не обосновывает инвестиции (см. юнит-экономику).
